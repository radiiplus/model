# Evaluation Landscape (Batch 1)

Checked 2026-11-23. This review inspected ten relevant canonical projects or benchmarks plus current research leads. No repositories, benchmark corpora, model weights, or packages were downloaded for this review. Commit hashes below pin the inspected upstream source state; the repo URLs in this document are commit-pinned. GitHub `git ls-remote` connectivity was verified in this Codespace. The first audit found no attached project checkout.

## Search and evidence method

Search variants used: (1) open-source language-model evaluation harness task/scorer frameworks; (2) claim-level factuality, RAG hallucination and evidence metrics; (3) abstention, calibration and contamination-aware benchmarks. Candidate pages/papers were checked against canonical repositories and source files where available. Project README statements are labeled as project claims; paper-reported findings remain paper claims; code-path descriptions below are source observations. No benchmark result was independently reproduced here. Commit dates are upstream activity indicators, not evidence of benchmark validity.

### Common comparison dimensions

For evaluation systems the model-centric measures (parameter count, model training stability, context scaling and KV-cache) are **not applicable**; they belong to the model/backend comparison ledger. Here compare task validity and coverage, deterministic-vs-judge scoring, corpus/license burden, dependency footprint, peak RSS/runtime for a pinned smoke subset, CPU/consumer portability, tests and reproduction instructions. No upstream repository was run here, so peak RSS, throughput and independent reproduction are **not measured** for all ten candidates. A README test command or passing upstream tests is not independent reproduction of reported benchmark results.

For Inspect AI and `simple-evals`, this pass evaluated the current canonical repository/source and did not identify a single peer-reviewed methods paper to rank alongside their implementation evidence. Where a paper is identified in the table, its results are scoped to the paper's evaluated tasks and setup; they do not validate the current repository's full behavior.

## Additional research leads

- **FactBench / VERIFY** (2024): paper proposes evidence retrieval and labels supported, unsupported and undecidable content units, and a refreshable in-the-wild factuality set. Search result/paper abstract indicates potential value for separating unverifiable from false; repository source, license, commit, judge reliability and runtime were not audited in this batch. Review before adoption: [paper](https://arxiv.org/abs/2410.22257).
- **VISTA** (ACL 2026): paper proposes sequential claim-level verification for conversational factuality and reports comparison with FActScore/judge baselines. It postdates many established tools; repository, license and independent reproduction remain unverified here. Review before adoption: [paper](https://aclanthology.org/2026.acl-long.1890/).
- **Know2Guess** (2026 search result): contamination-aware knowledge boundaries with answer/abstain zones, strict and robustness parsers, and refusal analysis. Very recent; only search-result abstract was seen, so repo, paper status, license, labels and methods need a direct source audit before treating it as a candidate.

## Recommendation for this batch

Retain the locally written standard-library scorer as the lightweight first harness. Use source designs from `lm-evaluation-harness`/Inspect for later backend integration, HELM for multidimensional reporting, FActScore/RAGTruth for claim labels, and AbstentionBench for answerability scenarios. No candidate is selected as the final benchmark suite. Avoid third-party judges for the first controlled tests: exact arithmetic, exact formatting, local unit assertions and hand-labeled evidence IDs provide deterministic checks. Any later model-based grader must be calibrated against blinded human labels, versioned, and reported separately.
