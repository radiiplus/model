# Batch 8: External Memory, Retrieval and Bounded Control

Checked 2026-11-23. Re-measured host: 8,327,024,640 bytes RAM, 5,766,475,776 bytes available, no swap; two allowed logical CPUs, no NVIDIA device, 37 GiB free on `/tmp`. Python 3.14.2; existing CPU PyTorch 2.15.0+cpu remained available but was not needed. No embedding packages or models were available: `sentence_transformers`, `faiss`, `qdrant_client`, Haystack, LlamaIndex and DSPy all absent in both system Python and the isolated Torch venv. No install, clone, model, data download or network service was used for the local experiment.

## Distinguish the mechanisms

| Mechanism | Where information lives | Update and retrieval | Main tradeoff |
|---|---|---|---|
| Recurrent model state (RWKV/Mamba family) | Fixed-size state inside a model instance while processing a token stream | Updated every token; not an external searchable document index | Bounded state, but exact facts may be compressed/forgotten; no source provenance, ordinary item deletion or stable cross-session store |
| Test-time learned memory (Titans, GradMem) | Learned memory vectors/parameters associated with an inference episode or context | Online update, in GradMem via inner-loop gradient steps | More adaptation compute and mutable state; possible interference/forgetting; source provenance, contradiction resolution and deletion need additional system design |
| External retrieval store (BM25/vector/ColBERT) | Explicit documents/chunks and metadata outside model weights | Search top-k; write/update/delete at a storage layer | Auditable and replaceable, but retrieval is not understanding; embedding models, indexes, freshness, access control and storage may be extra costs |
| Controller (RLM, Haystack/agent pipeline, custom loop) | Orchestration state, prompt/context, tool results and budgets | Chooses calls and context assembly | Can bound context or inspect large inputs, but adds latency/calls and tool-execution risk; it is neither a learned model memory nor a retrieval index by itself |

Batch 5's Mamba/RWKV source review remains relevant to internal recurrent state. The fixed state there is sequence history, not a user-editable knowledge base. RAG and controller components should be optional system layers; do not add parameters to the base model merely because retrieval is used.

## Local fixture and evaluation

The synthetic [knowledge base](../experiments/fixtures/tiny_knowledge_base.json) has 10 records: one exact duplicate with a weaker source, distractors, rare identifiers, two time-bounded museum schedules and two same-date contradictory status sources. Every item is fictional and CC0-1.0. The 9 [queries](../experiments/fixtures/tiny_retrieval_queries.json) include answerable, historical, stale/current, conflict and no-answer cases. Gold evidence IDs are explicit.

The standalone [retrieval/controller prototype](../experiments/retrieval_controller.py) compares distinct-term keyword overlap and BM25-style ranking (k=3). It has no embedding path because no local embedding model/package was present. The exact structured resolver filters by entity/attribute, `valid_from`/`valid_to`, source reliability, canonical duplicate lineage and current conflicts. A response is accepted only when its cited current evidence has exactly the returned value. A retrieved document alone does not establish support.

The first test run found two implementation/test issues: answer support checked that citation IDs existed but did not compare the cited current value to the returned answer, and a cache test incorrectly expected a lexically relevant updated document to disappear from search. The verifier and test were corrected, then regression coverage was added. A later metric test fixed precision@k to a fixed denominator when fewer than k candidates are returned. Failed test evidence is retained in the experiment log.

## Provenance, freshness and controller contract

Each document should retain immutable document/chunk ID, content hash, parent document, source/publisher URI, license/terms, acquisition time, parser/version, `valid_from`/`valid_to`, source reliability/authority and duplicate lineage. Each claim should record its exact cited chunk IDs and offsets plus answer/as-of time. Keep source text distinct from generated summaries. Contradiction handling should preserve both sources and either choose by explicit authority/time policy or abstain; never silently overwrite history.

Writes are explicit and provenance-required. Updates/deletes increment a memory version and invalidate retrieval/response caches; vector embeddings, lexical postings, duplicate aliases and downstream summaries must also be invalidated or rebuilt. A cached result is keyed by memory version, retriever/model version, query and permissions. Deletion must cover derived indexes and caches, not just the source row. Do not automatically persist model-generated claims as facts.

The bounded controller is a small state machine: retrieve at most one chunk per cycle, run evidence verification after each result, continue only on `needs_more`, stop on answer/conflict/no result/budget, at most 2 cycles. Per-query caps are 64 context-text tokens, 16 output tokens and 50 ms. It never evaluates user-generated code or accesses the network. An exhaustive-source flag is needed for mutable facts; the synthetic beacon query requires independent sources and abstains on the conflicting pair. A production evidence resolver must represent source authority and coverage rather than assuming search top-k found all evidence.

## Cost, failures and recommendation

- Keyword/BM25 needs a local text index and metadata, no embedding model or server; it can miss paraphrases and rank duplicates/lexical distractors. Keep as the first CPU baseline.
- Dense embeddings add a separate encoder checkpoint and per-document/query encoding. A flat FP32 index alone costs `4*N*d` bytes (e.g. 1M 384-dimensional vectors ~=1.54 GB, before IDs/metadata/index overhead); ANN trades exact recall for storage/search behavior. Do not download a model until lexical retrieval demonstrably fails on a licensed paraphrase set.
- ColBERT stores token vectors, often much larger than one vector/document; RAGatouille/ColBERT require weights and index construction. Defer until precision at lexical recall fails to meet a measured need.
- Qdrant adds a service and operational controls. For one-process consumer deployment, prefer an in-process index until corpus scale, concurrency or update requirements justify the server.
- External retrieval keeps source provenance and permits update/delete but can return stale, contradictory or irrelevant material. A separate claim verifier and abstention policy remain required.
- RLM recursively inspecting prompt data is a controller strategy; each subcall spends model compute. Its REPL code execution must be sandboxed. Add only if a measured long-input task benefits beyond direct retrieval.
- GradMem/Titans update internal learned state; their papers/code do not supply reliable document provenance or user-facing delete semantics. GradMem performs K inner gradient updates per context before reading memory, so each request adds at least K training-like forward/backward computations; meta-training through those updates adds second-order/backward-through-optimization work. Exact update FLOPs were not reported or measured here. Repeated updates can overfit the current context, interfere with other memories or forget prior information. Defer; test separately from RAG with exact recall, update/forgetting, interference and per-query compute measures.

**Recommendation:** keep the model small and stateless across requests by default; add optional external lexical retrieval with provenance, freshness filters, explicit source writes and deterministic claim checks. Use recurrent state for in-sequence context only. Treat learned test-time memory and recursive controllers as separate ablations. Search success is only candidate generation; the final answer still needs evidence support or abstention.
